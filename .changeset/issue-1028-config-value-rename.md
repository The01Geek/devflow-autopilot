- **The config migration now renames the `devflow` spellings inside your config, not just its top-level keys.** A new pass (`lib/migrate-config-values.py`, run by `scripts/scaffold-config.sh`, so it reaches both `install.sh --apply` and `/prflow:init`) rewrites the `agent_overrides` `devflow:<agent>` keys to `prflow:`, a `<!-- devflow:` workpad marker to `<!-- prflow:`, and a `DevFlow` entry in `docs.labels` / `deferred.labels` to `PRFlow` — so `.prflow/config.json` reads `prflow` / `PRFlow` throughout. Each is safe because every reader accepts both spellings in both directions; only the label *applied to new artifacts* changes, so rename the GitHub label itself if you want existing issues and pull requests to agree. The pass is idempotent, needs no shipped-workflow freshness gate, keeps a deliberately-falsy value from being coerced onto a default, and matches label entries whole rather than by substring so an unrelated label merely containing the word is left alone. If both spellings of one `agent_overrides` key are present and the current-spelled one holds a real edit rather than a scaffolded default, that key is refused and reported instead of clobbered. The pass leaves the frozen `workflows.devflow` / `workflows.devflow-review` toggles, `allowed_bots` GitHub logins and absolute workspace paths untouched, and says once — derived from what your config actually carries — which of those stay and why, pointing at the existing `DEVFLOW_*` environment freeze rather than restating it.
